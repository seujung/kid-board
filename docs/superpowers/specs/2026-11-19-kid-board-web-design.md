# 자녀용 할 일 보드 웹 앱 설계

작성일: 2026. 11. 19.

## 1. 의도와 배경

사용자는 자녀 2명의 할 일 보드를 벽에 붙인 iPad에 상시 표시하려고 합니다.
보드의 기능과 화면 규칙은 기존 설계 문서 `docs/superpowers/specs/2026-11-19-kid-board-design.md`(이하 "기존 설계")에서 확정했습니다.
기존 설계는 SwiftUI iPad 앱을 전제로 했습니다.

실제 기기는 iPad Air 2(모델 코드 `iPad5,4`)입니다.
이 iPad는 iPadOS 15.2이고 최대 15.8.x까지만 올릴 수 있습니다.
사용자는 기기를 바꿀 수 없습니다.

2026. 11. 19.에 네이티브 앱 설치를 시험했습니다.
Xcode 27.2와 Xcode 16.2 명령줄 도구 모두 이 iPad를 설치 대상으로 인식하지 않았습니다.
사용자의 Mac과 Mac mini는 모두 최신 macOS입니다.
그래서 네이티브 앱은 이 iPad에 설치할 수 없습니다.

이 문서는 같은 보드를 iPadOS 15 Safari의 홈 화면 웹 앱으로 만드는 설계입니다.

## 2. 기존 설계와의 관계

다음 내용은 기존 설계를 그대로 따릅니다. 이 문서는 반복하지 않습니다.

- 2장 목표, 비목표, 반목표 (아래 3장에서 바뀐 항목만 다룹니다)
- 7.1 용어
- 7.2 보드 화면 규칙 1~9
- 7.3 시간대와 카운트다운 규칙 1~8
- 7.3.1 야간 모드 규칙 1~3 (밝기 조절 부분은 6.6에서 바꿉니다)
- 7.4 날씨 규칙 1~5
- 7.5 부모 모드 (PIN 복구 방식은 6.10에서 바꿉니다)
- 9장 제가 정한 사항

기존 iPad 앱 구현에서 확정한 다음 판단도 따릅니다.

- 마감 시각 정각은 다음 시간대로 봅니다. 등교 시각 08:20:00이면 저녁 시간대입니다.
- 할 일이 0개인 날 잘 준비 시각이 지나면 "오늘 수고했어!"를 표시합니다.
- 오늘 할 일을 모두 끝내면 오늘 칸에도 별 도장을 찍습니다.
- 남은 시간이 1시간 이상이면 "1시간 29분 55초"처럼 시간까지 표시합니다.
- 잘 준비 시각이 등교 시각과 같거나 이르면 저장을 막습니다.
- 새 자녀를 추가하면 기본 시각을 넣습니다. 월~금 등교 08:20, 잘 준비 21:30, 토·일 등교 없음, 잘 준비 21:30입니다.
- 예시 데이터("첫째", "둘째")는 처음 한 번만 넣습니다. 자녀를 모두 지워도 다시 넣지 않습니다.
- 날씨 지역이 없으면 "지역을 설정해 주세요"를 표시하고 날씨 요청을 하지 않습니다.
- 부모 모드에서 날씨 지역을 바꾸면 진행 중인 요청을 취소하고, 이전 지역 날씨를 지우고, 즉시 새로 가져옵니다.
- PIN 잠금 상태(5회 실패, 1분)는 저장해서 앱을 다시 열어도 유지합니다.

## 3. 목표 변경

### 추가하는 목표

- iPadOS 15.2 Safari에서 홈 화면 웹 앱으로 동작합니다.
- 인터넷이 끊겨도 날씨를 뺀 모든 기능이 동작합니다.
- 부모가 데이터를 파일로 백업하고 복원할 수 있습니다.
- 할 일 제목과 자녀 이름은 키보드 받아쓰기로 입력할 수 있습니다.

### 없애는 목표

- 무료 계정 서명, 7일 만료, Mac mini 자동 재설치가 필요 없습니다.
- 서명 만료 경고와 재설치 후 사용법 유도 접근 안내가 필요 없습니다.
- 앱이 화면 밝기를 낮추는 기능은 웹에서 불가능해서 없앱니다.

### 추가하는 반목표

- Safari 데이터 삭제나 기기 교체로 자녀와 할 일 기록이 사라지는데 복구 수단이 없습니다.
- 새 버전 배포가 자녀가 쓰는 중에 화면을 갑자기 새로 고칩니다.
- iPad Air 2에서 화면이 끊기거나 1초 시계가 밀립니다.

## 4. 제약

- 기기: iPad Air 2, iPadOS 15.2 Safari. 화면은 가로 1024×768 CSS 픽셀입니다. 기존 iPad 앱 스크린숏(iPad Pro 13형)보다 작으므로 이 크기를 기준으로 배치합니다.
- 메모리 2GB, A8X 칩입니다. 매초 다시 그리는 범위를 최소로 줄입니다.
- 2026. 11. 19. iPad에서 확인한 결과는 다음과 같습니다.
  - 지원함: HTTPS, 서비스 워커, CSS flex `gap`, `Intl` 한국어 날짜
  - 지원하지 않음: `Array.prototype.at`, `structuredClone`
  - `navigator.storage.persist()`는 `false`를 반환했습니다(Mac Safari 기준).
- 쓰지 않을 기능: `Array.prototype.at`, `structuredClone`, CSS `:has()`, 컨테이너 쿼리, `dvh`·`svh` 단위, `backdrop-filter` 남용, Screen Wake Lock API(Safari 16.4부터).
- 배포 주소: `https://seujung.github.io/kid-board/` (GitHub Pages, 공개 저장소 `seujung/kid-board`)
- 저장소 커밋 작성자: `seujung hwan, Jung <digit82@gmail.com>`
- 외부 서버와 회원 가입은 없습니다. 데이터는 iPad 안에만 저장합니다.

## 5. 접근 방식

검토한 방식은 두 가지입니다.

1. **TypeScript + Vite + Preact, GitHub Actions로 Pages 배포 (선택)**
   - 규칙을 TypeScript로 옮기고 단위 테스트를 붙입니다.
   - 빌드 도구가 Safari 15에서 동작하는 코드로 변환합니다.
   - `main`에 push하면 GitHub Actions가 빌드하고 Pages에 배포합니다.
2. **빌드 없는 순수 HTML·JavaScript**
   - 배포는 단순합니다. 규칙과 화면이 많아서 관리와 테스트가 어렵습니다.

React는 iPad Air 2에서 매초 다시 그리기에 무거울 수 있어서 제외했습니다.
사용자가 1번을 선택했습니다.

## 6. 설계

### 6.1 저장소 구성

- 웹 앱 코드는 저장소의 `web/` 폴더에 둡니다.
- 기존 iPad 앱 코드(`App/`, `Packages/`, `scripts/`, `project.yml`)는 그대로 둡니다. 나중에 iPadOS 17 이상 iPad가 생기면 쓸 수 있습니다.
- 배포 워크플로는 `.github/workflows/pages.yml`입니다. `web/`를 빌드해서 Pages에 올립니다.
- GitHub Pages 설정의 Source를 "GitHub Actions"로 바꿔야 합니다. 사용자가 한 번 바꿉니다.
- 배포가 동작하면 시험 페이지용 `gh-pages` 브랜치를 지웁니다.

### 6.2 기술 구성

- 언어: TypeScript (strict)
- 화면: Preact
- 빌드: Vite. 빌드 대상은 `safari15`입니다. 앱의 기본 경로(`base`)는 `/kid-board/`입니다.
- 테스트: Vitest
- 외부 런타임 의존성은 Preact 하나로 제한합니다.

### 6.3 모듈

| 모듈 | 책임 | 기존 대응 |
|---|---|---|
| W1 도메인 | 날짜, 요일, 자녀, 할 일, 일정, 시각, 완료 기록 타입 | Task 1 |
| W2 일정 계산 | 날짜별 할 일, 요약, 일정 수정 분할 | Task 2 |
| W3 보드 상태 | 시간대, 카운트다운, 완료 가능 여부, 화면 문구 | Task 3 |
| W4 표시 규칙 | 야간 모드, 낮·밤 배경, 우산 안내 | Task 4 (서명 만료 읽기 제외) |
| W5 날씨 | Open-Meteo 예보·지역 검색, 30분 갱신, 3시간 기준 | Task 5 |
| W6 부모 잠금 | PIN 해시, 5회 실패 1분 잠금, 복구 문제 | Task 6 |
| W7 저장소 | IndexedDB 저장, 변경 알림, 예시 데이터, 버전 이전, 백업·복원 | Task 7 |
| W8 보드 화면 | 헤더, 자녀 패널, 카운트다운, 요일 줄, 할 일 카드, 도장, 축하 | Task 9 |
| W9 부모 모드 | 3초 진입, PIN, 자녀·할 일·시각·지역·기록·PIN 변경, 백업·복원 | Task 10 |
| W10 상시 표시 | 야간 검은 막, 오프라인, 새 버전 적용 시점 | Task 11 (밝기·만료 제외) |
| W11 배포 | GitHub Actions, Pages, 설치 안내 문서 | Task 8 대체 |

W1~W6은 화면과 분리한 순수 함수로 만듭니다.
기존 Swift 테스트(패키지 53개)의 입력과 기대값을 TypeScript 테스트로 옮겨 같은 동작을 확인합니다.

### 6.4 데이터 저장

1. 앱은 전체 데이터를 하나의 JSON 문서로 IndexedDB에 저장합니다. 문서에는 `schemaVersion` 숫자가 있습니다.
2. 앱이 문서를 읽을 때 `schemaVersion`이 낮으면 이전 함수로 올립니다. 이전 함수는 단위 테스트로 확인합니다.
3. 날짜는 `{year, month, day}` 숫자로 저장합니다. 시간대가 바뀌어도 날짜가 변하지 않습니다.
4. 날짜와 요일 계산은 iPad의 현재 시간대를 씁니다. 그레고리력만 씁니다.
5. 데이터가 바뀌면 저장소가 화면에 변경을 알립니다. 보드는 매초 전체 데이터를 다시 읽지 않습니다.
6. 앱은 처음 실행할 때 `navigator.storage.persist()`를 요청합니다. 결과와 관계없이 동작합니다.

### 6.5 백업과 복원

1. 부모 모드 메뉴에 "백업 파일 저장"과 "백업에서 복원"을 둡니다.
2. 백업 파일은 전체 데이터 JSON입니다. 파일 이름은 `kid-board-backup-YYYYMMDD.json`입니다. PIN 해시, 복구 코드 해시, 잠금 상태는 백업에 넣지 않습니다.
3. "백업 파일 저장"을 누르면 앱이 `navigator.share({ files })`로 공유 시트를 띄웁니다. 홈 화면 웹 앱에서 파일을 바로 내려받으면 앱으로 돌아오지 못할 수 있기 때문입니다.
   - 백업 저장 위치는 iCloud Drive입니다. 웹 앱은 iCloud Drive에 직접 쓸 수 없습니다. 그래서 부모가 공유 시트에서 "파일에 저장" > iCloud Drive > `할 일 보드 백업` 폴더를 고릅니다. iPad를 초기화하거나 바꿔도 백업이 남습니다.
   - 공유 시트 위에 "공유 화면에서 '파일에 저장' > iCloud Drive를 고르세요."를 안내 문구로 표시합니다.
   - `navigator.share`가 파일 공유를 지원하지 않으면 `<a download>`로 내려받습니다.
4. "백업에서 복원"은 파일 선택 입력(`<input type="file" accept="application/json">`)을 엽니다. 부모가 iCloud Drive의 `할 일 보드 백업` 폴더에서 파일을 고릅니다.
5. 복원하면 앱이 파일의 `schemaVersion`을 확인하고 필요하면 이전 함수를 적용합니다. 그다음 "지금 데이터를 백업 내용으로 바꿀까요?" 확인 후 바꿉니다. PIN과 복구 코드는 지금 기기의 값을 유지합니다.
6. 파일 형식이 맞지 않으면 "백업 파일을 읽을 수 없어요"를 표시하고 아무것도 바꾸지 않습니다.
7. 마지막 백업 후 7일이 지나면 부모 모드 첫 화면에 "백업한 지 N일 지났어요"를 표시합니다. 보드 화면에는 표시하지 않습니다.
8. 사용법 유도 접근이 켜져 있으면 공유 시트와 파일 선택이 막힐 수 있습니다. 설치 안내 문서에 "백업·복원 전에 홈 버튼을 세 번 눌러 사용법 유도 접근을 잠시 끄십시오"를 적습니다.
9. 백업 형식은 웹 앱 전용입니다. 기존 네이티브 앱이 이 파일을 가져오는 기능은 만들지 않습니다. 형식은 `web/` 안의 문서에 적어 둡니다.

### 6.6 야간 모드

- 22:00~06:00에 보드 위에 불투명도 약 0.92의 검은 막을 덮고 시계만 크게 어둡게 표시합니다.
- 웹은 화면 밝기를 바꿀 수 없습니다. 백라이트는 켜진 상태로 남습니다. 설치 안내 문서에 이 한계를 적습니다.
- 화면을 누르면 30초 동안 보드를 표시합니다. 부모 모드가 열려 있는 동안에는 어둡게 하지 않습니다.

### 6.7 오프라인과 새 버전

1. 서비스 워커가 빌드 결과 파일을 모두 캐시합니다. 날씨 요청은 캐시하지 않습니다.
2. 새 버전이 배포되면 서비스 워커가 새 파일을 미리 받습니다.
3. 앱은 자녀가 쓰는 중에 새로 고치지 않습니다. 새 버전은 다음 세 경우에만 적용합니다.
   - 야간 모드 시간(22:00~06:00)에 입력이 5분 이상 없을 때
   - 부모가 부모 모드에서 "새 버전 적용"을 누를 때
   - 앱이 종료된 뒤 다시 열릴 때 (다시 열리는 순간 이미 화면이 새로 시작되므로 허용합니다)
4. 부모 모드 첫 화면에 현재 버전과 "새 버전 있음" 여부를 표시합니다.

### 6.8 화면

- 기존 iPad 앱의 보드 디자인을 따릅니다. 기준 스크린숏은 `.superpowers/sdd/2026-11-19-kid-board/screens/a16-morning.png`입니다(git 제외 폴더라서 이 Mac에만 있습니다).
  - 위쪽: 날짜, `HH:mm:ss` 큰 시계, 낮·밤 풍경, 날씨 카드
  - 아래쪽: 자녀별 테마 색 패널(첫째 coral, 둘째 sky), 아바타와 이름, 카운트다운 카드와 진행 막대, 월~일 요일 칸과 별 도장, 할 일 카드와 "참 잘했어요" 도장, "지금 하자!" 노란 표시
- 낮·밤 풍경은 SVG로 새로 그립니다. 참조 이미지(Threads 게시글)의 그림을 복제하지 않습니다.
- 1024×768에서 할 일 5개가 스크롤 없이 보여야 합니다. 할 일이 더 많으면 패널 안에서 스크롤합니다.
- 매초 다시 그리는 부분은 시계와 카운트다운뿐입니다. 나머지는 데이터 변경, 시간대 경계, 날짜 변경 때만 다시 그립니다.
- 부모 모드 입력 칸(할 일 제목, 자녀 이름) 아래에 "키보드의 🎤 버튼을 누르면 말로 입력할 수 있어요."를 표시합니다.
- PIN 해시는 Web Crypto(`crypto.subtle.digest("SHA-256")`)로 계산합니다.

### 6.9 iPad 설정 (설치 안내 문서에 적을 내용)

1. Safari로 배포 주소를 열고 공유 > "홈 화면에 추가"를 누릅니다.
2. 설정 > 디스플레이 및 밝기 > 자동 잠금을 "안 함"으로 정합니다. 웹 앱은 화면 꺼짐을 직접 막지 못합니다.
3. 설정 > 손쉬운 사용 > 사용법 유도 접근을 켜고, 홈 화면 앱을 연 상태에서 시작합니다.
4. 설정 > 일반 > 키보드에서 한국어 키보드를 추가하고 "받아쓰기 활성화"를 켭니다.
5. 설정 > Apple 계정 > iCloud에서 iCloud Drive를 켭니다. 파일 앱의 iCloud Drive에 `할 일 보드 백업` 폴더를 만듭니다.
6. Safari 설정에서 "방문 기록 및 웹사이트 데이터 지우기"를 누르면 데이터가 사라진다는 점을 적습니다. 백업 방법도 적습니다.

### 6.10 PIN 복구 코드

기존 설계의 곱셈 문제 복구를 복구 코드로 바꿉니다. 9살 자녀가 두 자리 곱셈을 풀 수 있기 때문입니다.

1. 부모가 PIN을 처음 정하면 앱이 8자리 숫자 복구 코드를 만들어 한 번 표시합니다. 문구는 "이 복구 코드를 따로 적어 두세요. 다시 보여 드리지 않아요."입니다.
2. 부모가 "적어 두었어요"를 눌러야 다음으로 넘어갑니다.
3. 앱은 복구 코드를 PIN과 같은 방식(salt + SHA-256)으로 해시해서 저장합니다. 원문은 저장하지 않습니다.
4. PIN 입력 화면의 "PIN을 잊었어요"를 누르면 복구 코드 입력 화면이 열립니다. 코드가 맞으면 새 PIN을 정합니다. 복구 코드는 그대로 유지합니다.
5. 복구 코드 입력도 PIN과 같은 잠금 규칙을 씁니다. 5회 연속 틀리면 1분 동안 입력을 막습니다.
6. 부모 모드에 "복구 코드 새로 만들기"를 둡니다. 새 코드를 한 번 표시하고 이전 코드는 쓸 수 없게 됩니다.
7. 복구 코드를 잃어버리고 PIN도 잊으면 앱 안에서는 복구할 수 없습니다. 이때는 Safari 웹사이트 데이터를 지우고 백업 파일로 복원합니다. 설치 안내 문서에 이 절차를 적습니다.

### 6.11 테스트

- W1~W7은 Vitest 단위 테스트로 확인합니다. 기존 Swift 테스트의 입력과 기대값을 옮깁니다.
- W7은 IndexedDB 대체 구현(`fake-indexeddb`, 개발 의존성)으로 테스트합니다.
- 화면은 개발 서버에서 1024×768 크기로 확인합니다. 시각을 고정하는 개발 전용 주소 옵션(`?fixedNow=ISO8601`)을 둡니다. 이 옵션은 배포 빌드에서 동작하지 않습니다.
- 마지막으로 iPad Air 2에서 다음을 확인합니다.
  1. 홈 화면 앱으로 전체 화면 실행
  2. 가로 1024×768 배치에서 잘림이나 겹침 없음
  3. 앱을 완전히 닫았다 다시 열어도 데이터 유지
  4. 받아쓰기로 할 일 제목 입력
  5. Wi-Fi를 끄고 다시 열어도 보드 동작
  6. 1초 시계가 밀리지 않음
  7. 백업 파일 저장과 복원

## 7. 사용자가 정한 사항

- 대상 기기는 iPad Air 2(iPadOS 15)이고 바꾸지 않습니다.
- 네이티브 앱 대신 웹 앱으로 만듭니다.
- 기술 구성은 TypeScript + Vite + Preact, GitHub Actions 배포입니다.
- 저장소는 공개 저장소 `seujung/kid-board`, 기본 브랜치 `main`입니다.
- 음성 입력은 키보드 받아쓰기로 충분합니다.
- 보드 디자인은 기존 iPad 앱 디자인을 따릅니다.
- PIN 복구는 곱셈 문제 대신 8자리 복구 코드로 합니다.
- 백업 파일은 iCloud Drive에 저장합니다.

## 8. 빌더에게 맡기는 부분

- 컴포넌트 구성과 파일 나누기
- CSS 작성 방식(일반 CSS 또는 CSS 모듈)

- 서비스 워커 구현 방식(직접 작성 또는 빌드 플러그인). 플러그인을 쓰면 개발 의존성으로만 둡니다.
- 아이콘 이미지(180×180, 512×512 PNG)

## 9. 제가 정한 사항 (사용자 확인 필요)

- 백업에 PIN 해시, 복구 코드 해시, 잠금 상태를 넣지 않습니다. 백업 파일이 유출되어도 PIN을 추측할 단서가 남지 않게 하기 위해서입니다.
- iCloud Drive의 `할 일 보드 백업` 폴더를 백업 위치로 정했습니다. 공유 시트 안내 문구로 이 위치를 안내합니다.
- 새 버전은 야간 무입력 5분, 부모의 직접 적용, 앱 재실행 때만 반영합니다.
- 백업 7일 경과 안내는 부모 모드에만 표시합니다.
- 부모 모드 입력 칸에 받아쓰기 안내 문구를 넣습니다.
- 네이티브 앱의 웹 백업 가져오기는 만들지 않습니다.
- 복구 코드는 8자리 숫자이고, 복구 코드 입력에도 5회 실패 1분 잠금을 씁니다.
